# 스티커 · Sticker

**나와 코딩 에이전트가 함께 쓰는, 작고 비공개인 이슈 작업실.** 프로젝트 → 버전 → 이슈를 연결하고, 댓글·변경 기록·파일·이미지·문서·링크를 한 곳에 붙입니다. 종이 카드 느낌의 한국어 UI와 보드/목록 보기를 제공합니다.

이 저장소는 실제 SQLite 영속 저장을 사용하는 설치형 앱입니다. 온라인 데모나 공개 서비스가 아니며, 기본 비밀번호·실사용 토큰·가짜 운영 데이터는 포함하지 않습니다.

검증 결과와 아직 실행하지 못한 검증은 [검증 기록](docs/VERIFICATION.md)에 정리했습니다.

## 빠른 설치 — Docker Compose

요구 사항: Docker Server Engine 28.3.3 이상(해당 Engine을 포함한 Docker Desktop)과 Compose v2. 표준 무암호 로컬 시작은 서버 버전을 확인하며 구버전·미확인 버전에서는 시작하지 않습니다. 기본 웹 앱과 Docker MCP에는 호스트 Node/Python, GitHub 계정이나 개인 폴더가 필요하지 않습니다. 호스트에서 직접 개발/실행하는 선택적 경로만 Node.js 24 이상을 사용합니다. [설치·이전·환경 독립성 안내](docs/INSTALL.md).

```bash
cp .env.example .env
chmod 600 .env
bash scripts/start.sh
docker compose logs --tail=50 sticker
```

브라우저에서 **http://localhost:8787** 을 열면 비밀번호 없이 바로 사용합니다. 같은 컴퓨터의 다른 사용자·프로그램도 소유자로 접근할 수 있으므로 신뢰하는 개인 컴퓨터에서만 사용하세요. 첫 실행은 비어 있습니다. 프로젝트와 첫 이슈를 만들면 시작됩니다.

- 포트는 기본적으로 **127.0.0.1에만 바인딩**됩니다. 같은 컴퓨터에서만 접속할 수 있습니다. 이 설명은 현재 컴퓨터의 로컬 Docker Engine/Desktop 컨텍스트를 전제로 합니다. 선택한 Docker context/`DOCKER_HOST`는 바꾸지 않으며, 원격 daemon을 선택했다면 loopback과 신뢰 대상은 그 Docker 호스트 기준이고 현재 브라우저의 접속을 보장하지 않습니다.
- DB와 첨부 파일은 `sticker_data` 이름의 Compose 영속 볼륨에 함께 저장됩니다. 컨테이너를 다시 만들어도 보존됩니다.
- `docker compose down`은 데이터를 보존합니다. **`docker compose down -v`는 데이터를 삭제합니다.**
- `STICKER_PORT`를 바꿀 때 `APP_ORIGIN`도 같은 포트로 바꾸세요.
- 코드 업데이트는 먼저 `bash scripts/backup.sh backups/sticker-backup.tar.gz`로 백업하고, `docker compose stop sticker`로 명시적으로 중지한 뒤 `bash scripts/start.sh`로 적용합니다.
- 컨테이너는 비루트 `node` 사용자로 실행되며, 루트 파일시스템은 읽기 전용입니다. 기본 설치에는 호스트 폴더 마운트가 없습니다.
- 에이전트는 선택 사항입니다. 운영자 JSON 파일을 읽을 때만 `compose.agents.yaml`을 적용합니다. 기존 `AGENT_CONFIG_PATH` 사용자는 [이전 안내](docs/INSTALL.md#선택-에이전트--mcp)를 확인하세요.
- 새 체크아웃의 실제 Docker 검증은 `bash scripts/verify-container.sh`와 [컨테이너 CI](.github/workflows/container.yml)로 실행합니다. 검증은 전용 임시 프로젝트/볼륨만 사용합니다.

### 휴대폰 또는 다른 컴퓨터에서 쓰려면

UI는 작은 화면을 지원하지만 기본 설치는 의도적으로 로컬 전용입니다. 원격 접속은 로컬 기본 경로와 별개이며 `LOCAL_OWNER_MODE=off`, 고유한 `OWNER_PASSWORD` 및 별도 네트워크/TLS 설정이 필요합니다. **인증 없는 공개 포트로 바꾸지 마세요.** 운영자가 관리하는 비공개 네트워크와 HTTPS 역방향 프록시를 구성한 뒤 `APP_ORIGIN`을 실제 HTTPS 주소로, `SECURE_COOKIES=true`로 설정하세요. 이 소스 배포는 해당 네트워크 변경이나 공개 배포를 수행하지 않습니다.

## 사용 흐름

1. **프로젝트**: 이름·키·색상을 지정합니다. `APP-1`처럼 이슈 키가 프로젝트별로 발급됩니다.
2. **버전**: 계획/출시/보관 상태와 날짜를 기록합니다. 이슈의 **목표 / 발견 / 수정 버전**은 서로 별개이며 같은 프로젝트의 버전만 선택됩니다.
3. **이슈**: 백로그 → 준비 → 진행 → 대기 → 구현 완료 → 종결. **구현 완료(done)**는 에이전트도 기록할 수 있지만, **종결(closed)**은 소유자의 확인입니다.
4. **자료**: 웹 UI에서 파일을 최대 20 MiB까지 올리거나 http/https 링크를 붙입니다. 링크는 서버가 방문하지 않습니다. 첨부 파일은 인증된 사용자/범위 내 에이전트에게만 제공됩니다.
5. **동시 수정**: 오래된 revision으로 저장하면 409 충돌을 반환합니다. 최신 이슈를 다시 읽은 뒤 변경을 적용합니다. 다른 에이전트의 수정을 조용히 덮어쓰지 않습니다.

**대기 상태는 자동 실행되지 않습니다.** 이 앱은 작업 기록 시스템이지 셸 실행기/에이전트 오케스트레이터가 아닙니다. 에이전트 상태는 타임스탬프가 있는 **자기 보고**입니다. 5분이 지나면 오래된 보고로 표시되며, 최신 보고도 프로세스가 실제로 실행 중이라는 증거는 아닙니다.

## 에이전트 / MCP 연결

에이전트는 소유자 비밀번호를 사용하지 않습니다. 운영자가 직접 만든 고엔트로피 토큰의 **SHA-256 해시**, 에이전트 이름, 프로젝트 범위, 쓰기 허용 여부를 설정합니다. 범위 밖 자료 접근과 소유자 사칭은 서버에서 거부됩니다. 설정을 만들지 않으면 에이전트 접근은 비활성입니다.

→ [MCP와 Codex 설정 안내](docs/MCP.md)

이 배포에서는 실제 토큰을 발급하거나 사용자의 Codex 설정을 변경하지 않았습니다.

## 백업과 복원

DB만 복사하면 첨부 파일과 불일치할 수 있습니다. 제공 스크립트는 Bash·tar·awk·grep이 있는 환경(Linux/macOS/WSL)에서 실행하며, 서비스를 정지한 상태에서 **SQLite DB + uploads 전체**를 복사합니다. Docker Compose 프로젝트 폴더에서 실행하세요. 비밀번호·에이전트 설정은 백업에 포함되지 않으므로 별도로 안전하게 보관하세요.

```bash
# 기존에 실행 중이었다면 백업 후 다시 시작합니다. 같은 파일을 덮어쓰지 않습니다.
bash scripts/backup.sh backups/sticker-2026-10-28.tar.gz

# 복원은 현재 DB/첨부 전체를 교체합니다. 먼저 현재 데이터를 백업하세요.
# 본인이 만든 신뢰할 수 있는 백업만 복원하세요.
bash scripts/restore.sh backups/sticker-2026-10-28.tar.gz --replace-data
# 복원 후 서비스는 정지 상태입니다. 확인 후 명시적으로 시작합니다.
bash scripts/start.sh
```

복원은 경로 탈출·심볼릭 링크를 거부하고, 임시 디렉터리의 DB를 읽기 전용으로 검증한 뒤 기존 데이터를 교체합니다. 0바이트/다른 앱의 DB, 지원하지 않는 스키마 버전, 필수 테이블·컬럼 누락, `integrity_check`/`foreign_key_check` 오류, UUID 파일 키 오류, 누락되거나 크기가 다른 첨부 파일은 거부합니다. 지원 스키마는 설치된 릴리스의 누적 마이그레이션 목록으로 검증하며, 더 새로운 스키마의 백업은 거절합니다. 실행 중인 다른 백업/복원 작업과 동시에 사용하지 마세요. 백업에는 비공개 이슈와 파일이 있으므로 접근을 제한하고, 필요하면 별도로 암호화하세요.

## 로컬 개발 / 검증

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run test:production
# .env 자동 로딩은 하지 않습니다. 이 셸에 OWNER_PASSWORD를 직접 설정하세요.
# 실행 예: OWNER_PASSWORD='<본인 비밀번호>' npm start
npm start
```

개발 중에는 `APP_ORIGIN=http://localhost:5173 npm run dev`로 API를, 별도 셸에서 `npm run dev:client`로 Vite를 실행합니다. API 프로세스에 `OWNER_PASSWORD`도 설정되어 있어야 합니다. API 기본 주소는 `http://localhost:8787`, Vite는 `http://localhost:5173`입니다. 브라우저 테스트는 `npm run build` 후 `npx playwright install chromium`과 `npm run test:ui`로 실행합니다. 기본 테스트는 포트 8788의 임시 작업 공간을 생성하고 종료 시 삭제하므로 실제 운영 데이터에 쓰지 않습니다. `STICKER_TEST_BASE_URL`을 별도로 지정하면 해당 테스트 인스턴스를 사용하므로 운영 주소를 지정하지 마세요. 테스트 자격증명은 임시 fixture에만 사용합니다.

구조: `server/domain.ts` (공통 권한/업무 규칙), `server/app.ts` (HTTP/인증/파일), `server/mcp.ts` (STDIO → 동일 HTTP API), `client/` (React), `tests/` (실제 SQLite·HTTP·MCP 테스트). 설계와 구현 범위는 [design](docs/superpowers/specs/2026-10-28-sticker-design.md), API 계약은 [API-CONTRACT](docs/API-CONTRACT.md)를 참고하세요.

## 의도적인 범위와 운영 주의

- 활동 기록은 이슈 단위입니다. 프로젝트/버전 메타데이터 변경에는 별도 감사 로그가 없습니다. 이슈를 삭제하면 연결된 댓글·활동 기록·첨부 자료도 삭제되므로 보존이 필요하면 삭제 전에 백업하세요.
- 개인 소유자 + 코딩 에이전트용입니다. 팀 초대, 공개 공유 링크, 이메일 알림, 실시간 협업, 실행 자동화는 없습니다.
- 첨부 자료는 인증된 작업실 안에서 공유합니다. HTML/SVG는 실행 가능한 인라인 미리보기를 제공하지 않습니다. 악성코드 스캔은 포함하지 않으므로 신뢰할 수 없는 파일은 실행하지 마세요.
- 세션은 서버 메모리에 보관되어 재시작하면 다시 로그인해야 합니다. DB/파일은 유지됩니다.
- SQLite 기반 단일 인스턴스입니다. 여러 앱 복제본을 같은 볼륨으로 띄우거나 네트워크 파일시스템에서 공유하지 마세요.
- 에이전트 설정 변경은 서버 재시작 후 반영됩니다. 토큰 폐기는 해당 항목을 지우고 재시작하면 됩니다.
- Node 24의 `node:sqlite`에 관한 런타임 경고가 출력될 수 있습니다.
- Docker 데몬이 없는 환경에서는 이미지 빌드/컨테이너 실행을 검증할 수 없습니다. 최종 전달의 검증 보고서에서 실제 실행 여부를 확인하세요.

### 실행별 에이전트 기록과 확인함

에이전트 실행마다 별도 세션·불변 이벤트를 남기고, 입력 요청·결과 검토를 사용자 확인함에서 처리할 수 있습니다. 자기 보고는 실행 증명이 아니며 답변·종결로 작업을 자동 실행하지 않습니다. 자세한 API, 호환성, v1→v2 데이터 이전 및 검증 방법은 [에이전트 세션과 사용자 확인함](docs/AGENT-SESSIONS.md)을 참고하세요.
