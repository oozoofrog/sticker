# GitHub 읽기 전용 근거

프로젝트의 **GitHub 연결**은 소유자 전용입니다. 기본 공급자는 비활성이고 모든 프로젝트는 미연결입니다. 핵심 이슈·버전·리소스 기능에는 GitHub 계정이나 토큰이 필요하지 않습니다.

## 선택적 운영 설정

1. 운영자가 외부 GitHub 조회를 허용할 때만 `GITHUB_READ_ENABLED=true`를 설정합니다. 공개 저장소는 토큰이 필요 없습니다.
2. 인증 저장소가 필요한 경우에만 별도 읽기 전용 마운트 파일을 준비하고 `GITHUB_CREDENTIAL_CONFIG_PATH`를 지정합니다. Docker 예시는 `/app/config/github-credentials.json`이며 호스트의 파일 위치는 운영자가 정합니다. 저장소·이미지·백업 데이터 디렉터리에 비밀을 넣지 않습니다.
3. 파일 형식은 `{ "reference-name": { "label": "연결 주체 이름", "token": "운영자가 별도로 제공하는 값" } }`입니다. 실제 비밀은 UI/MCP로 입력하지 않습니다. `label`은 비밀이 아닌 식별 이름이어야 합니다. 파일은 일반 파일이어야 하며 심볼릭 링크는 거절합니다. 변경 후 앱을 재시작합니다.
4. 소유자가 프로젝트에서 저장소 소유자/이름과 공개 또는 설정된 인증 참조를 선택하고 읽기 조회에 명시적으로 동의합니다. **연결 저장은 네트워크 조회를 하지 않습니다.** 연결 확인과 근거 재확인은 별도 수동 동작입니다.

클라이언트는 `https://api.github.com`으로만 GET 요청을 보내며 리디렉션을 따르지 않습니다. 이것은 토큰 자체의 최소 권한을 검증했다는 뜻이 아닙니다. UI의 토큰 권한 범위는 계속 **미검증**입니다. 실제 토큰 생성·권한 부여·계정 연결은 이 기능의 구현 또는 설치만으로 승인되지 않습니다.

## 근거와 상태

이슈의 **GitHub 근거**에서 정확한 `https://github.com/owner/repository/pull/123` 또는 40자리 SHA 커밋 URL을 등록합니다. 선택 저장소 밖 URL, 다른 호스트, 사용자정보·쿼리·fragment·인코딩된 경로는 거절합니다. 같은 이슈의 같은 정규 URL은 중복 생성하지 않습니다.

- 캐시 목록 읽기는 외부 요청을 하지 않습니다. 자동 폴링/웹훅/재시도는 없습니다.
- 수동 재확인은 PR 헤드와 정확한 SHA의 체크 및 상태를 수집하고 헤드를 다시 읽습니다. 헤드가 바뀌면 이전 SHA 검증 결과는 보존하되 현재 CI는 미확인입니다.
- 페이지 수·응답 크기·시간 제한, 중복/불일치 결과, 1000개 체크 스위트 제공자 한계 등 완전성을 보장할 수 없는 경우 성공으로 표시하지 않습니다. skipped/neutral/cancelled 역시 성공이 아닙니다.
- 권한·요청 제한·네트워크 오류는 마지막 성공 결과와 시각을 보존하고 오래된 상태로 표시합니다. 연결 해제나 저장소 변경 뒤 기존 근거는 현재 상태로 사용하지 않습니다.
- 연결 확인도 revision을 증가시키는 CAS 변경입니다. 같은 revision의 동시 완료는 먼저 수락된 결과만 저장하며 이후 완료는409입니다. 연결/해제/확인과 겹친 오래된 근거 응답도 수락하지 않습니다.
- PR 병합이나 CI 성공은 이슈 종료/버전 출시/에이전트 실행을 유발하지 않습니다.

## API / MCP

인증과 프로젝트 범위는 기존 이슈 권한과 동일합니다. 연결 설정 조회·변경·확인은 소유자만 가능합니다. 닫힌 이슈 및 읽기 전용 에이전트는 근거를 변경/재확인할 수 없습니다.

- `GET/PUT/DELETE /api/projects/:id/github`: 연결 설정. PUT/DELETE는 `revision`, `confirm:true` 필수.
- `POST /api/projects/:id/github/verify`: 수동 연결 확인. 동일한 CAS/명시 확인 필수.
- `GET/POST /api/issues/:id/github-evidence`: 캐시 목록/URL 등록. 등록은 `url`, `issueRevision` 필수.
- `GET/DELETE /api/github-evidence/:id`: 캐시 조회/연결 근거 삭제. 삭제는 `revision` 필수.
- `POST /api/github-evidence/:id/refresh`: 수동 외부 확인. `revision` 필수.
- MCP `sticker_get_github_evidence({issueId})`: 같은 범위의 캐시 근거만 읽습니다. GitHub 쓰기/병합/CI실행 도구는 없습니다.

응답·활동에는 토큰 또는 자격증명 참조를 포함하지 않습니다. upstream 본문/예외는 노출하지 않고 제한된 오류 코드만 사용합니다. schema8은 기존 schema1–7 데이터를 보존하며 연결과 근거만 추가합니다. 공급자 설정은 앱 데이터 백업과 별도로 관리합니다.

## 검증

모든 개발·브라우저 검증은 주입한 결정적 fixture 또는 비활성 공급자를 사용합니다. 실제 GitHub 자격증명이나 네트워크는 사용하지 않습니다. `tests/container-github-smoke.mjs initialize|verify`는 비활성 공급자에서 연결/근거가 재시작·복원 후 유지되고 기존 이슈가 변경되지 않음을 검사합니다. 실제 Docker/브라우저 판정은 해당 CI 실행 결과로 확인합니다.

## 저장소 선택

연결 화면에서 기존 공개 연결의 계정 또는 설치 운영자가 이미 설정한 인증 표시명을 고른 다음 저장소를 선택합니다. 정상 경로에는 owner, 저장소 이름, 자격증명 참조 입력이 필요하지 않습니다. 공개 조회에는 인증 토큰을 보내지 않고, 인증 목록은 그 기존 자격증명이 볼 수 있는 저장소만 표시합니다. 목록 조회 자체는 토큰의 최소 권한을 검증하지 않습니다.

목록은 명시적으로 한 페이지씩 가져옵니다. 한 번에30개, 최대100페이지이며 마지막 페이지에 추가 결과 가능성이 남으면 한도 상태를 표시합니다. 새로고침·주체 변경·서버 재시작 또는15분 경과 후에는 다시 선택해야 할 수 있습니다. 선택 ID는 프로젝트·연결 revision·조회 주체에 묶인 일시 값이며 자격증명 참조나 비밀을 포함하지 않습니다. 목록과 저장 사이에 계정/저장소/연결이 바뀌면 기존 연결을 덮어쓰지 않습니다.

새 설치에 공개 연결 정보와 설정된 인증이 둘 다 없으면 `선택 가능한 계정 없음`을 표시합니다. 이 경로가 GitHub 로그인이나 OAuth 동의를 자동 생성하는 것은 아닙니다. 기존 HTTP 연결 계약을 사용하는 운영 설정은 계속 지원하지만 정상 화면은 선택형입니다. 별도 계정 온보딩은 이 변경 범위에 포함하지 않습니다.

저장 응답을 받지 못했을 때는 `저장 결과 확인`으로 현재 저장소·조회 방식·동일 자격증명·예상 revision을 다시 비교합니다. 다른 변경, 만료 또는 서버 재시작으로 확인할 수 없으면 성공으로 표시하지 않고 최신 연결을 검토하게 합니다.
